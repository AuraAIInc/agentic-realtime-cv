Behavior notes (all from the traces + terminal log):

- **Every run got poisoned period data and recovered.** The prompts hand the
  agent replay-local period ids (1–4), but `tracking__get_period_detail`
  queries the *production* tracking server, whose ids 1–4 are 2024-era visits
  (E1's "visit 1" came back as 174,311 frames spanning May–Nov 2024). All 12
  agents noticed the mismatch ("visit record looks inconsistent") and pivoted
  to judging from raw images. 11 period-detail calls were wasted (~2–8 s and
  ~4k tokens each).
- **Every zoom request failed, and verdicts still landed.** All 16
  `box`/`max_side` crops errored with `ModuleNotFoundError: No module named
  'PIL'` — the image server at 10.0.0.165 still runs pre-fix code with no
  Pillow. Agents adapted by comparing full frames against the cat profiles.
  All 58 plain reads succeeded, so the ISO→filename conversion in the
  prompts worked every time.
- **Verdict pattern is coherent.** All three T2 relabels overturned
  (`keep_original`: the camera was right, nearness stole the box); T4
  overturned (`link_continuation`: same cat, restart wrong); T6 split upheld
  (`confirm_split` — frames show two cats at once, see below); all three T7
  interpolations upheld; all three period verdicts upheld; P6 → `merge`.
- One transient model-API 503 (+ retry) during E12; no verdict was lost.

## 6. Evaluation: did validation improve the pipeline?

**Upheld / overturned by code** (agent verdict vs tracker proposal):

| Code | Upheld | Overturned | Reading |
| ---- | ------ | ---------- | ------- |
| T2 (relabel) | 0/3 | 3/3 | nearness-only relabeling is wrong every time it was sampled |
| T4 (reset) | 0/1 | 1/1 | the wipe discarded a continuing track |
| T6 (split) | 1/1 | 0/1 | teleport split was right |
| T7 (interpolation) | 3/3 | 0/3 | guessed runs were fine |
| P5/P2 (periods) | 3/3 | 0/3 | visit verdicts were real |
| P6 (merge) | 1/1 | 0/1 | visits 3+4 are one (applied) |

**What improved.** The loop works end-to-end with zero dropped verdicts:
queue → agent → parse → journal → apply → chart → memory. It caught and fixed
2 mislabeled rows, merged a fragmented visit, and confirmed 169 rows plus 3
interpolated runs and 1 split — genuinely raising confidence in the
interpolation and period machinery.

**What limited the improvement** (honest accounting):

1. **Recall, not precision, is the bottleneck.** The agent overturned 3/3
   sampled T2 relabels, but only 3 of 772 relabels were escalated. ~770
   likely-mislabeled Qbo rows passed through untouched — `validated.png` is
   visually identical to `revised.png` for exactly this reason. Fixing T2
   escalation recall (or the underlying relabel greed) multiplies the value
   of every future validation run far more than judging the current 12
   better.
2. **Two apply-stage bugs ate correct verdicts** (found in this session's
   outputs, fixes not yet implemented):
   - *Same-frame T2 cross-talk:* `_t2` matches rows by (timestamp, cat) with
     no box check, so E7's handler matched E6's just-flipped row and flipped
     it back. Final row: `cat_id 25, validated_by E6-T2,E7-T2,E9-P6,E11-P2` —
     E6's `keep_original` (= 26) is recorded but not reflected.
   - *Order-dependent vacuous op:* E9's merge (seq 9) emptied period 4 before
     E12's keep (seq 12) ran, so E12 matched nothing; the shared `verdict`
     field also shows only the last writer (`keep`, hiding the T2 verdicts).
3. **Two integration faults taxed every run** (external, both previously
   flagged): replay-local period ids collide with production tracking ids
   (11 wasted `get_period_detail` calls, all 2024 data), and the image
   server lacks Pillow (16/16 zoom calls failed). The agents routed around
   both, at the cost of extra turns and tokens.

**Cost of the session's validation:** 600,684 tokens, $0.77, ~12.6 min for
12 escalations — ≈ 63 s, ≈ 50k tokens, ≈ $0.064 per escalation (detail §7).
Tracking itself cost ~2 s and $0.

Bottom line: the validation workflow is a working, well-instrumented safety
net that confirmed the tracker's strong parts (interpolation, splits,
periods) and correctly indicted its weak part (nearness relabeling) — but
until escalation recall and the two apply bugs are fixed, each run corrects a
sample while the population passes through.

## 9. Issues found (ranked)

1. **Tracker relabeled 772/818 Qb detections as Qbo; only 3 escalated.**
   Core recall gap (§2, §6). Population-level fix needed, not a 13th prompt.
2. **`tracking__get_period_detail` returns production visits for replay-local
   ids.** Every validation run burns its first turn on 2024 data (§4). Needs
   id namespacing or a replay-aware tracking source.
3. **Image server has no Pillow and runs pre-fix code** (`ModuleNotFoundError`
   × 16). Pull + restart 10.0.0.165.
4. **Same-frame T2 cross-talk undoes verdicts** (E6/E7, §5). `_t2` needs box
   discrimination.
5. **Op application order can vacate verdicts** (E12 after E9, §5); shared
   `verdict` field keeps only the last writer.
6. **Stale memory recents across runs** (E1 brief, §8). Run-scope the keys.
7. Minor: E11-P2's "winner cat 25" vs final "no cat assigned" for period 3 —
   escalation captured decision-time state, `periods.jsonl` the post-cutoff
   verdict; worth one clarifying line in the P2 prompt. P2's "1 original
   frames" plural wart is still open.
