## 0. Pitch

✅ **方向**：我们的主题是日常生活，所以 pitch **最终落脚在它怎么改变大家的生活**：可以讲
情感、讲具体的生活场景、讲更大的 impact。技术上的创新照样讲清楚，作为"怎么做到的"。

💡 **草稿**：

> 你不在家的时候，总想知道猫好不好：谁吃了饭，谁睡了一下午，胆小的那只今天出来过没有。
> 现在的智能摄像头分不清两只猫，也永远不会针对*你家*变得更好。我们把一个 24 小时运行的
> 小 CV 模型和 Meta 的大模型结合起来。大模型不只是回答问题，它会自己行动：遇到没把握的时刻
> 主动问你，了解你家里什么最重要，并且**教会小模型**。它每周都更懂你家一点，你不用看任何
> 录像也能安心。

差异化点，按分量排序：

1. ✅ **针对每个场景持续学习**（核心）：大模型当老师，CV 模型当学生。这回答了评审一定会问的
   问题："为什么不把每一帧都丢给 VLM？"我们的回答是成本、延迟和隐私：便宜的模型一直在跑，
   贵的模型只处理难的情况，并把结果变成训练数据。
2. ✅ **会自主行动的大模型**。回答问题、做总结、用对话自定义标签，单看这些已经不算独特，
   因为大的摄像头厂商也在加 LLM 功能。新的地方在于大模型还会通过各种方式主动行动：
   - 主动请用户确认或标注困难的情况，用来增强 CV 模型；
   - 主动问用户哪些场景、物体、人或宠物重要，然后侧重优化这些；
   - 不等用户问，就去改进模型、降低延迟、提供 insights。

   最终目的是给用户更好的体验：提供更丰富、更准确的信息。
3. ✅ **个人管家的数据来源**。这个系统对家里的了解，可以成为个人管家数据的重要一部分。
   像 Muse 这样的管家可以跟这个系统结合，更懂用户。

✅ 在 demo 视频里明确提到竞品，展示差别。

## 2. 系统：三部分加学习闭环

```text
                    ┌──────────────── 用户：文字 / 语音 ────────────────┐
                    ▼                                                  │
 摄像头 (2 fps) ─► CV 模型 (YOLO + 活动) ─► tracker ─► MEMORY ◄─► AGENT (Meta 模型)
                         ▲                        │                    │
                         │                   困难场景？                  │
                         │                        ▼                    │
                         │                 ESCALATION：大模型 + 工具 ─► 标签
                         │                                              │
                         └──── 重新训练 ◄── 数据集 ◄── (人工确认 ❓) ◄────┘
```

### 第一部分：Agentic system

用户跟系统交互：提问、要总结等等。系统也会自己行动：主动问用户要标签和优先级，发提醒。

| | 状态 |
| --- | --- |
| 调用工具的 agent，连 3 个 MCP server（Pi 上的摄像头、存图服务器、tracker 状态） | 已有，比赛前写的（`mcp_agent`、`tracking_mcp`） |
| 用对话自定义标签和区域（`--labels`） | 已有，比赛前写的（PR #4） |
| 从 OpenAI 换成 Meta 模型 | **新做**，必须做（第一轮 pass/fail） |
| 基于记忆的总结（"猫今天都干了什么"） | ✅ 新做 |
| **主动行动的 agent**：请用户确认或标注困难的情况；问用户哪些场景、物体、人或宠物重要，并优先优化 | ✅ 新做。具体行为 💡 |
| 主动提醒（"如果 Qbo 10 点前还没吃饭就告诉我"） | 💡 新做 |
| 语音提问（Muse Voice Transcribe） | 💡 新做，可以考虑 |
| 找*任意*物体，不只是猫（SAM 3.1 开放词汇分割） | ✅ 不做。框架可以泛化过去 |

### 第二部分：Memory

agent 回答问题时可以调取的东西。例如问"现在在这个位置的是哪只猫？"，可以调取五分钟内的
检测结果，以及每只猫的状态（在移动还是在睡觉等）。有图像类、工具类，也有文字类（已经总结
好的）。

| 类型 | 来源 | 状态 |
| --- | --- | --- |
| 短期状态 | tracker 缓存（约 15 秒）、实时状态、当前时段、最后出现、最后一次移动（`tracking_mcp`） | 已有 |
| 长期结构化数据 | MySQL 的 `period`、`revised_detection`，每天/每小时统计（`daily_job.py`） | 已有 |
| 图像 | image server（SSD） | 已有 |
| 静态文字知识 | 猫的描述、参考照片、标签、区域（`agent_data/`） | 已有（PR #4） |
| **总结好的文字记忆** | 由大模型写，可以按时间 / 猫 / 文字内容检索 | ✅ **新做**。间隔 ❓（每个时段？每小时？每天？），存储和检索方式 ❓ |

💡 总结里避免健康判断（"比平时吃得少"可以；"可能生病了"不行）。AI 医疗建议在主办方的
禁止列表里。

### 第三部分：Escalation 和持续学习

正常情况下 CV 模型大约 2 fps，每一帧都有检测结果。但真实情况下会有很多 **gap**（检测不到）
和 **jump**（检测框偏离）。场景困难时，我们 escalate 到大模型，让它调用工具找出正确的标签。
这些标签作为额外数据，继续训练 CV 模型。

| | 状态 |
| --- | --- |
| Escalation 任务：身份检查、轨迹物理检查、活动标注；先用规则，再调模型；图片预算；`send_to_human` | 已有，比赛前写的（PR #4，未合并） |
| **触发条件**：什么算困难场景，从实时数据流里自动判断 | **新做**。具体定义 ❓，Muyang 决定（gap 多长、jump 多大、身份翻转、低置信度、没见过的物体？） |
| **标签 → 数据集**：把 agent 的输出变成训练集（现在只写进 jsonl 日志，`flaskr/scr/auto_label.py` 不读它） | **新做** |
| **重新训练检测模型**（YOLO） | **新做**。现有的 `auto_train.py` 跑在 AWS EC2 上 |
| **重新训练活动模型**（单独的姿势/活动模型） | **新做** |
| 训练前要不要人工确认（主动行动的 agent 就是在这里问用户） | ❓ Muyang 决定：总是、从不、还是只在不确定时？ |
| 在用户本地训练，还是传回云端 | ❓ Muyang 决定；利弊见下表 |

**本地 vs 云端（❓ Muyang 决定；下表的分析是 💡）：**

| | 设备端 / 家里的盒子 | 云端（现在的 EC2 方案） |
| --- | --- | --- |
| 隐私 | 强：画面不出家门 | 较弱 |
| Bonus 奖 | 如果 Muse Spark Open / Glimmer 也在本地跑，可以冲 Best Open Weight（$10K） | 无 |
| 9 天内的工程量 | 更难（Pi 或盒子上的算力） | 有现成的 pipeline 可以改 |

## 3. 实验（💡）

现在还没有标注数据，所以"会变好"这个说法需要实验支撑。能证明它的最小版本：

1. **评测集**：从自家摄像头手标几百帧，刻意覆盖困难情况（gap、jump、两只猫靠得很近、光线暗）。
2. **基线**：用现在的 YOLO + tracker 跑评测集，记录身份认错率、gap/jump 比例，以及活动分类
   准确率（等活动模型做出来之后）。
3. **跑几轮闭环**：在另一段时间的数据上跑 escalation，用它的标签建数据集，重新训练，再在同一
   个评测集上测一次。时间允许就跑 2-3 轮，这样上手流程的 demo（§4）可以用真实数字展示一步步
   变好。
4. **汇报**：前后对比写进 README 和视频。

❓ 指标和评测集大小：谁来定？（💡 建议 Muyang，因为最了解 tracker 会在哪里出错）

## 4. Demo（✅ 方式已定）

评审会看产品"现场能不能用"，但摄像头是我们家里的一个 Pi。所以 demo 用录好的一段时间来跑：

1. **过去的一段时间，里面有真实的事件。** 用户可以体验：
   - **Insights**：对这段时间向大模型自由提问，得到回答。
   - **整段时间的 tracking 和标签**。
2. **上手流程**：从刚安装到标注完成。展示模型怎么跟用户交互拿到标签（主动行动的 agent，
   §2 第一部分），以及表现怎么一步步变好。

上手流程是预先设定好的，但它来自真实数据和真实的模型提升（§3 的实验），我们会这样说明。

- 💡 部署出来，任何人都可以从网页或 repo 里试。
- 💡 **3 分钟视频大纲**（初稿，脚本会不断改）：
  1. 0:00-0:20 开场：两只长得几乎一样的猫，摄像头把它们搞混了。
  2. 0:20-1:00 跟它对话：提问、找东西、要总结，用语音。
  3. 1:00-2:00 闭环：CV 出错 → escalation 修正 → 重新训练 → 前后对比数字。
  4. 2:00-2:40 自定义："猫坐在帐篷里的时候给它打个标签"。展示可以推广到猫以外的场景。
  5. 2:40-3:00 竞品 vs 我们；用了哪些 Meta 模型；这周新做了什么。
- ❓ 家里的画面公开（repo、视频、X 帖子）可以接受吗？
