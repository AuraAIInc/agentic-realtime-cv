How we use Meta products

MUSE SPARK 1.3: THE MODEL THE PRODUCT RUNS ON
Supervisor agent: when the tracker on the Raspberry Pi raises a doubt, Muse Spark receives a plain-English question with the frames to inspect and both cats' written profiles. It investigates with tools (camera, stored images, tracker history, reference photos) and skills loaded on demand, then returns a verdict in a strict schema that rewrites the record. In the demo, it reviewed 12 doubts in 5 calls and returned 12 of 12 valid verdicts.
Joint review: related doubts are merged into one call with an answer schema built at runtime, so the agent reasons across cases and fetches each frame once.
Activity labeler: a vision call labels each trusted visit with an activity, the cat's appearance and the background.
Memory engine: Muse Spark checks whether new observations contradict stable memory and compresses cells into zones, and hours into days and weeks, as plain-language summaries.
Chat agent: answers questions such as "Is any cat on camera right now?" and adds labels and zones on request.
Across the build: 124 agent sessions, 1,058 tool calls, every session answered, 52% of input tokens cached, $9.22 in total.

MUSE SAM 3.1: THE GROUND TRUTH
SAM 3.1 proposed cat regions from segmentation masks and Muse Spark named each cat. This labeled every frame of the demo window with F1 0.794, against 0.612 for a single vision model, and gave us an honest yardstick for every result. The same labels can retrain the small detector.

MUSE WONDER: THE DESIGN
We used the deepest-reasoning tier early, where a wrong design costs the most: the doubt taxonomy, the verdict contracts, and the spatial-temporal memory architecture.

MUSE GLIMMER: LOCAL AND PRIVATE DEPLOYMENT
The camera server and correctors run on the device, and Muse Glimmer is the on-device model path, so footage can stay at home. It is the basis of our next step: giving a personal AI agent these eyes locally.

MUSE CODE: HOW WE BUILT IT
The pipeline, agent, memory system and tests were built in Muse Code in small, verified steps. Workflow skills with focused subagents handled large multi-file changes, voice input captured design ideas, and the design docs and reports were written next to the code.

META MODEL API
We relied on images returned inside tool results, multi-turn chaining, strict JSON schema output (including schemas built at runtime) and cached input pricing. A probe we ran found intermittent errors on chained image turns, and we designed a retry around it. We chose Standard pricing over the cheaper Contributor tier, because customers' home footage must never be used for training.

PLANNED
Muse Voice Transcribe for spoken questions, Muse Image with Muse Wonder for a daily recap of each cat's day, and Muse Spark Open for private reasoning on the owner's own hardware.
